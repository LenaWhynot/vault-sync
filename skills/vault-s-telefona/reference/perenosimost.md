# Переносимость — справочник навыка vault-s-telefona

Читать: облачная сессия падает на каждом инструменте · правлю хуки · «на маке
работает, в облаке нет».

## Симптом

Облачный агент клонирует репо и на КАЖДОМ вызове инструмента получает
`can't open file ...` или `command not found`. Сессия непригодна: заблокированы
и Bash, и Read, и Edit — починить изнутри нельзя, нужен человек.

## Причина

`.claude/settings.json` лежит в git, а значит его хуки едут во все клоны. Если в
командах зашиты пути одной машины — `/opt/homebrew/bin/python3`,
`/Users/<имя>/...` — в другой среде их нет.

## Правило

```
интерпретатор  → из PATH:  python3
путь к скрипту → "$CLAUDE_PROJECT_DIR/<путь>"   ← ТОЛЬКО двойные кавычки
```

**Одинарные кавычки — главная ловушка.** Shell не раскрывает в них переменную, и
путь превращается в `<репо>/$CLAUDE_PROJECT_DIR/...`. Симптом неотличим от
«скрипт потерялся».

## Как править settings.json

Только через JSON-парсер (`json.load` → правка значений → `json.dumps`).
Строковой заменой в сыром тексте легко вписать двойную кавычку внутрь
JSON-строки без экранирования и получить битый файл — а битый `settings.json`
это снова заблокированная сессия.

## Проверка ДО установки

Собрать кандидата в отдельном файле и проверить три вещи, и только потом класть
на место (атомарно, `os.replace`):

```python
json.loads(text)                      # 1. валиден
# 2. каждая команда раскрывается настоящим shell в существующий файл:
#    zsh -c 'for a in <команда>; do printf "%s\n" "$a"; done'
#    → первый аргумент ищем через shutil.which, второй — Path(...).is_file()
assert "/Users/" not in text and "/opt/homebrew" not in text   # 3. чисто
```

## Что должно уехать вместе с хуками

Скрипты, на которые они ссылаются, обязаны быть **в git** и жить на stdlib —
иначе в облаке они не найдутся или не запустятся. Проверить:
`git ls-files <скрипт>` и `grep -E '^(import|from) ' <скрипт>`.
