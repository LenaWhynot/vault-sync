# Автомёрж облачных веток — справочник навыка vault-s-telefona

Читать: работа с телефона не доезжает до компьютера · настраиваю автомёрж ·
безопасность слияния.

## Зачем

Облачные агенты (Claude Code on the web, Codex cloud) пушат работу в СВОЮ ветку
(`claude/*`, `codex/*`), а компьютер подтягивает только `main`. Без слияния
работа с телефона не доезжает никогда. В живом vault так повисли 4 ветки за
месяц — в одной лежала готовая заметка в память.

**Ручной Merge в GitHub — не решение.** Шаг, который делает человек, не будет
делаться; на это и был расчёт, когда схему проектировали.

## Механика

Задание раз в 15 минут **и при включении компьютера** (`RunAtLoad`): fetch →
для каждой ветки `claude/*`, `codex/*` посмотреть, не влита ли уже → проверить
denylist → проверить сводимость → слить → push.

Три обязательные детали, каждая проверена на отказе:

1. **Общий flock с синком.** Иначе слияние и автокоммит дерутся за индекс.
2. **Работать на грязном дереве через stash.** На живой машине дерево грязное
   почти всегда; требование чистоты = слияние не случится никогда (поймано на
   тесте: пропускался каждый тик).
3. **Сводимость проверять через `git merge-tree --write-tree` ДО слияния** —
   не трогая рабочее дерево.

## Denylist: ничего исполняемого

Автомёрж вливает чужую работу без просмотра, поэтому запрещено всё, что
исполняется или управляет самим git:

```python
DENY_DIRS  = {".claude", ".github", ".githooks", "scripts"}
DENY_FILES = {".mcp.json", ".gitattributes", ".gitmodules"}   # плюс всё, что начинается с .env
```

**Почему `.githooks` критичен:** при `core.hooksPath=.githooks` хук лежит В РЕПО
и запускается при каждом коммите. Влить ветку с подменённым `pre-commit` = дать
чужому коду выполниться на машине при ближайшем автокоммите, то есть за минуты.
`.gitattributes` задаёт правила слияния, `.gitmodules` тянет чужой код.

**Сравнивать компоненты пути, а не префикс строки,** и в нижнем регистре:

```python
parts = [q.lower() for q in pathlib.PurePosixPath(path).parts]
```

`startswith("scripts/")` пропускает `<проект>/<имя>/scripts/deploy.sh`, а macOS
регистронезависим — `Scripts/` это та же папка.

**Защита в глубину:** слияние делать с `-c core.hooksPath=<пустой каталог>` —
merge создаёт коммит, а коммит дёргает хуки; автомату чужие хуки исполнять
незачем.

## Что автомат не берёт

Ветки из denylist и ветки с конфликтом остаются ждать + уведомление ОС. Это
правильно: там нужен человеческий взгляд.

## Как проверять такое перед включением

Собрать игрушечный репозиторий (bare origin + клон) и прогнать четыре сценария:
обычная ветка вливается · ветка в denylist придерживается · конфликтная
придерживается и main цел · незакоммиченные правки переживают прогон. Отдельно —
ветка, подменяющая `pre-commit` на запись файла-маркера: маркер не должен
появиться. Плюс `--dry-run` для первого запуска на живом репо.
