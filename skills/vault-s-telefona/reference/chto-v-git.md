# Что класть в git — справочник навыка vault-s-telefona

Читать: настраиваю схему с нуля · «что класть в гит, а что нет» · репозиторий распух.

## Принцип: режем слоем, а не доменом

Соблазн — «папка здоровья личная, не пушим её». Тогда с телефона не будет ни
выводов, ни протоколов, и схема бесполезна. Правильный рез проходит **внутри**
домена: курированный текст едет, сырьё остаётся.

| Едет в git | Остаётся на диске |
|---|---|
| выводы, протоколы, заметки, знание | сырые выгрузки, сканы, PDF, геном |
| стратегия, голос, правила, память | сырые диалоги и голосовые |
| агенты, скиллы, конвенции | медиа: видео, аудио, исходники монтажа |
| журналы и хэндофф | данные трекеров (посуточные дампы) |
| — | `.env`, `.mcp.json`, локальные настройки |

Ориентир по порядку величин из живого vault: **15 ГБ на диске → 295 МБ в git**,
1427 из 1911 markdown-файлов. Текст почти весь; разница — медиа и сырьё.

## Отдельно: приватность механизмом, а не дисциплиной

Конвенция `*.private.md` в `.gitignore` — быстрый рубильник «только для моих
глаз» в любой папке, не требующий думать про пути. То же для целого класса:
`<домен>/coaching/*-session-*.md`.

## Проверки, а не вера

```bash
gh repo view <owner>/<repo> --json isPrivate        # приватный?
git check-ignore -v <файл>                          # почему файл не в git
git ls-files | wc -l                                # сколько реально уехало
```

Последняя особенно нужна, когда кажется, что файл «должен быть в репо»:
`check-ignore` покажет строку `.gitignore`, которая его срезала. Если правила
нет — файл просто не добавлен, это другая проблема.

## Граница, которую надо назвать вслух

Всё, что не уехало, **с телефона недоступно**. Разбор анализов по исходным PDF,
монтаж, работа с сырыми выгрузками — только за компьютером. Это стоит сказать
человеку прямо при настройке, иначе он обнаружит это в неудачный момент.
